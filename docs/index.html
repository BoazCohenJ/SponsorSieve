SponsorSieve

Find podcast ads with a small model that runs on your CPU.

SponsorSieve is a 151 MB classifier trained only to spot sponsor reads, network ad breaks and show self-promotion in podcast transcripts. It needs no LLM, API key or GPU.

Use it

pip install "sponsorsieve[audio]"

sponsorsieve detect episode.mp3               # transcribe locally, list the ads
sponsorsieve detect transcript.json           # or use a transcript you already have
sponsorsieve clean episode.mp3 -o clean.mp3   # cut the ads out (needs ffmpeg)
sponsorsieve serve --port 8765                # HTTP API for ad removers
from sponsorsieve import Detector
ads = Detector().detect(segments)   # [{"start", "end", "text"}] -> [{"start", "end", "score", "kind"}]

Self-hosted ad removers such as podly and MinusPod send each transcript to an LLM. sponsorsieve serve offers the same job behind a small local HTTP endpoint, so those tools can call it in place of the LLM.

Measured on the MinusPod benchmark corpus: 15 real episodes, 20.4 hours, 58 human-verified ads, and no show from it used in training. An ad counts as found when predictions cover at least 30% of it. This is the project's own scoring script, not MinusPod's leaderboard metric.

Where it slips: on tech-news shows it sometimes flags hosts discussing products, and it misses some short network-inserted spots. English only.

How it was made

  • 283 recent episodes from about 100 popular US podcasts, transcribed with Whisper large-v3-turbo.
  • Ads labeled by a local open-weight LLM (Qwen 3.5 9B) in two passes: find candidate ads, then re-check each one.
  • ModernBERT-base fine-tuned to tag every token as content, ad or self-promo, then exported to ONNX and quantized to int8, which picks the same label as PyTorch on every token tested.
  • No SponsorBlock data was used. The whole pipeline is in the repo.
